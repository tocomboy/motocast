# 주행 날씨 요청 계약 v1

로컬 계산/요청 계약이다. 배포된 API 또는 인증 성공 증거가 아니다. 근거는 제품 정본 ROUTE-008 및 `docs/work/research/2026-09-08-android-ride-requirements.md` 3–5절, Q14·Q19다.

`remaining.json`은 개인 데이터가 없는 합성 예시다. Android의 `contracts/journey-weather/remaining.json`과 바이트가 같으며, Kotlin 요청 생성 결과도 JSON 값이 일치한다. 출발→휴식→동일 장소 2회→목적지의 방문 순서를 보존한다. 30분 휴식 중 20분이 지났으므로 10분 후 출발한다.

## 요청 경계

- `schemaVersion=1`, UUID `journeyId`/`requestId`, 0 이상 정수 `routeRevision`으로 주행·호출·경로를 구분한다.
- `source`는 `owned/tripId` 또는 `shared/token`이다. 형식 검사는 권한 확인이 아니다. 후속 endpoint는 활성 회원, 소유권 또는 공유 만료·회수·스냅샷 접근을 먼저 확인해야 한다. 공유 token은 로그/오류에 기록하지 않는다.
- `course`는 서버 정본과 대조할 전체 순서/ID/좌표/체류 시간이다. 중복 ID·좌표를 합치지 않는다. 권한 확인 후 서버에서 읽은 코스가 일치하지 않으면 다시 계획해야 한다. 클라이언트 코스를 그대로 정본 인자로 전달해서는 안 된다.
- `position`은 한국 범위 좌표, 정확도 50m 이하, 관측 시각이다. 서버 기준 30초 초과 과거/5초 초과 미래 위치를 거절한다. 앱은 단조 시간 기준 30초도 검사한다. 기술 초기값이며 GPS의 진위를 보장하지 않는다.
- `progress`는 현재 방문 순서, PENDING/ARRIVED, 도착 시각, 명시적으로 건너뛴 과거 순서다. 출발/최종 방문 건너뛰기, 미래/중복/역순 skip, 최종 도착 후 요청을 거절한다. 사용자 진행 정보로 경로를 계획할 뿐 접근 권한을 부여하지 않는다.

## 계산과 연동

`remainingJourneyPlan`은 도착한 장소의 잔여 체류만 적용하고, 지연 시 현재 시각에서 출발한다. 이미 이탈했다면 다음 차례의 방문부터 계산한다. `buildJourneyWeatherTimeline`은 남은 방문마다 이륜차 안전 조건을 통과한 실제 도로와 도로별 소요시간을 받는다. 연결 끊김·잘못된 끝점·순서 누락·24시간 이상 일정은 거절한다. 도로 내부는 누적 길이에 비례한 예상 위치이며 실제 순간 속도나 기상 실측이 아니다.

현재 시각부터 최대 120분, 10분 간격과 방문 도착/출발 경계를 표본으로 만든다. 이 **표본 간격**은 구현 초기값이며 **외부 조회의 기본 10분 간격**과 별개다. 표본마다 외부 API를 호출해도 된다는 의미가 아니며 격자·예보 발표/대상 시간으로 중복 통합해야 한다. 최종 도착 후 표본을 만들지 않는다.

Android `JourneyWeatherSchedule`은 기본 10분(설정 주입 가능), 진행 중 1건, 새 경로 ETA 준비, 경로 변경 후 기존 예보 제외, 실패/오래됨 표시용 상태, 종료/복원 뒤 과거 응답 거절을 제공한다. 예산 정책은 다음 호출 시각을 늦출 수 있고 이전 예보의 만료를 연장하지 않는다. 서버의 실제 예산 차감/분산 캐시/동시성 보호를 대신하지 않는다.

최초에는 위치·경로 준비 후 조회하며, 복구 시 기존 다음 조회 시각을 유지한다. 이미 예정 시각이 지났으면 준비 후 한 번만 조회한다. 실패는 다음 정기 시점에 재시도한다. 2026-09-22 사용자 확정이며 앱은 요청 전에 다음 시각을 암호화 저장한다. 예산 연장 단계는 별도 미확정이다.

## 서비스 연결 상태 — 2026-09-22

소유/공유 source와 계정 식별자, 다음 조회 시각을 암호화 주행 저장에 연결했다. 별도 `journey-route`/`journey-weather` endpoint는 활성 회원과 서버 정본을 확인하고 이륜차 안전 도로, ETA·표본, 격자·모델·발표 회차별 공유 캐시와 호출 전 예산 확보를 사용한다. 기존 `weather-timeline`의 저장 경로 결속과 20분 재사용은 유지한다. 예보 응답의 식별자·진척·도로·표본 시각·실제 수치·유효기간을 Android에서 검증한다.

Figma W01–W06 카드와 전면 위치 추적 서비스의 취소·복구·GPS 단절을 연결했다. 가장 가까운 강수를 우선하고 없으면 다음 행선지의 날씨를 표시한다. 예보가 2시간 범위 밖이면 확보한 예상 경로의 날씨로 구분하며 목적지 예보라고 주장하지 않는다.
