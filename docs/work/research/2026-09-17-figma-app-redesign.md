## READY interface contract

- Explicit home / editor / summary / collections views with browser navigation and existing public-share entry preserved. Reuse provider and request-gating orchestration; split presentation and dialogs by responsibility.
- Home: separate new-route and saved-route actions, motorcycle to the right with breathing room; recent owned courses and real empty state.
- Editor: origin, stable ordered waypoint occurrences, destination, reset beneath destination, schedule entry, common favorites. Arrow reordering recomputes visible labels without wrapping. Preserve current stop kinds and safety limits.
- Search: full-screen mobile, centered desktop dialog; verified provider selections, stale-response cancellation, name/address hierarchy, zero-result/error/retry states.
- Schedule: calendar and separate hour/minute choices with confirm/cancel, past-date/time rejection, fresh schedule for saved courses. Date/time changes preserve an explicitly pending collection-share intention while invalidating old approvals.
- Summary: map and readable time/weather cards, actual total/ride/rest/arrival values, weather emoji and text, edit and share/save actions. Unknown/stale weather remains explicit.
- Sharing retains full server-built preview and separate explicit publish. Saving persists the complete course without date/time and refreshes home/list. Existing version/delete/revoke management remains reachable.
- The received-summary new-schedule action retrieves a minimal reusable course through authenticated `get_shared_course` / same-origin POST, then opens the editor with a blank schedule. It does not automatically save, calculate or publish. Anonymous snapshot resolution never includes verification proofs. Private course and bearer remain only in component memory, with hash-change/unmount response isolation.
- Favorites are one per-user set of at most three, used in all three place roles, not a global cross-account list. Persistence uses a narrow owner-only database boundary; route and collection use still revalidates signed provider proof.
- Responsive: <=767px 20px gutters / full-screen search / bottom dialogs / one-column cards; 768-1199px 32px gutters / 360px editor / two-column saved cards; >=1200px max1280px content / 456px editor / three-column saved cards. The approved intermediate-width note permits vertically arranged results when space is insufficient: map/weather summary stacks below 1024px while editor and collection breakpoints remain unchanged. Keep 44px minimum controls, keyboard focus/escape/return and bounded modal scrolling.
