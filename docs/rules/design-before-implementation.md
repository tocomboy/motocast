# 화면 디자인 선행 규칙

사용자 확정: 2026-09-22. 웹과 Android의 새 화면·시트·대화상자 및 기존 화면의 큰 구성 변경에 적용한다.

1. 제품 정본과 현재 동작을 읽고 기존 [MOTOCAST Figma](https://www.figma.com/design/wVNriNWb1OlF21DVq8rqlJ)를 확인한다. 기존 원본은 보존하고 컴포넌트·색상·서체·간격을 재사용한다.
2. 화면 코드를 작성하기 전에 Figma에서 화면과 필요한 정상·로딩·빈 상태·오류·권한·복구·확인 상태를 디자인한다. 기존 확정 디자인으로 충분하면 해당 노드를 재사용하고 차이만 기록한다.
3. 디자인 Issue(또는 PR) 본문에 구현 화면/상태와 Figma 노드, 진입·뒤로·닫기·확정 동작, 스크롤·키보드·안전 영역·큰 글자 동작을 연결한다. 실제로 제공하지 않는 기능이나 데이터를 디자인에서 제공 중인 것처럼 표시하지 않는다.
4. 디자인을 렌더링하여 간격·줄바꿈·버튼·상태 구분을 확인하고 사용자에게 검토 가능한 링크/미리보기를 제시한 뒤 화면 구현을 진행한다. 확정된 제품 결정을 다시 묻지 않는다. 실제로 새 제품 선택이 필요한 부분만 질문하며, 디자인 선행 규칙 자체가 매번 별도 승인을 요구하지는 않는다.
5. 구현은 시안과 같게 만든다. 구현 후 같은 화면·상태를 시안과 나란히 비교해 남은 차이를 0으로 만들고, 차이가 필요하면 코드에서 임의로 두지 말고 시안을 먼저 고친 뒤 사용자에게 알린다(제품 정본과 충돌하는 시안은 정본에 맞춰 시안을 고친다). 실제 기기 또는 에뮬레이터의 결과를 별도로 기록한다. Figma 시안 완료를 앱 적용이나 기기 검증 완료로 보고하지 않는다.

## Figma 페이지 구성

화면·상태마다 최신본이 하나만 보이게 한다(사용자 확정 2026-10-07, 전역 디자인 원본 규칙).

- `현재 · v2 · …` (`284:2253`): 출시된 화면과 디자인 체계만 둔다.
- `작업 중 · …` (`389:12914`): Issue마다 섹션을 만들고 이름에 Issue 번호·상태(시안 / 구현 중 / 적용 vX.Y.Z)·목표 버전을 붙인다.
- `보관 · …`: 대체된 시안. 페이지나 프레임에 대체 시점과 대체한 노드를 표시하고 삭제하지 않는다.
- 출시(Production) 검증을 마친 같은 작업에서 해당 섹션의 시안을 현재 페이지로 옮기고, 대체된 현재 프레임은 보관으로 옮기며, Issue의 노드 대응표를 최종 노드로 갱신한다.

## Android 기준

- 대표 시안: Galaxy S23+ 에뮬레이터 설정에 대응하는 384×832 논리 화면. 기존 390×844 Figma 원본을 덮어쓰지 않는다.
- 320 폭, 큰 글자 1.3배 이상, 넓은 화면에서도 내용과 주요 동작에 접근할 수 있어야 한다. 고정 화면 캡처만으로 반응형 검증을 대신하지 않는다.
- 기본 좌우 여백 20, 관련 항목 간격 8/12/16/24, 터치 영역 최소 48. 좁은 폭/큰 글자에서 버튼은 세로 배치하고 문구는 줄바꿈한다.
- 긴 내용은 세로 스크롤하고 시스템 바·키보드에 가려지지 않게 한다. 색만으로 상태를 구분하지 않고 상태 이름을 함께 표시한다.

## 지침 적용 근거

[OpenAI의 프로젝트 AGENTS.md 안내](https://learn.chatgpt.com/docs/agent-configuration/agents-md#layer-project-instructions)는 전역 지침을 상속하는 저장소 지침을 지원한다. 디자인 선행은 OpenAI의 일반 의무가 아니라 이 프로젝트 사용자가 확정한 작업 순서다. 이번 변경은 프로젝트 두 곳에만 적용하며 개인 전역 지침·모델·권한 정책은 변경하지 않는다.
